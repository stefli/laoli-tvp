# 科技快播旁白审稿标准（播报口语 · 顺畅好听）

旁白先当**电视/电台科技新闻口播稿**写，再交给 TTS。书面堆料、清单轰炸、英文专名连发 = 听着吃力，一律退回重写。事实仍只来自 `SOURCES.md`；数字默认阿拉伯数字。

---

## 一、硬门槛（不过不许进 TTS）

成片前对 `voice_01…07` 全文做审稿。任一条不过 → 改稿，**禁止**先渲再将就。

1. **出声读一遍**：作者（或执行者）必须用正常语速默读/出声读完全部 7 句。卡壳、换气不够、需要回头看才能懂 → 改。
2. **一句一意**：每一拍旁白只推进一个信息点。禁止「机制 + 名单 + 口径」揉进同一句。
3. **听感优先于信息密度**：宁可少报一个专名，也不要让听众皱眉。细节留给画面大字/卡片/`PUBLISH.md`。
4. **禁止播报元话语**：不要说「口径要分清」「结论：」「规格以…为准」「本条按章节…」「以成片章节为准」——直接陈述事实。
5. **禁止书面破折号堆砌**：少用 `——`、长串顿号清单、英文冒号夹汉语。优先短句 + 句号/逗号换气。
6. **禁止成片/时间码口播（硬禁）**：旁白是对外新闻播报，不是导播笔记。禁止「大约 13 秒起」「从 00:13」「章节 XX 秒」「按章节走」「以成片章节为准」等。时间码与章节秒数只上画面字卡或 `PUBLISH.md`，旁白只说功能本身。

---

## 二、句长与节奏

| 规则 | 标准 |
| --- | --- |
| 每拍字数 | 目标 **28–42 汉字**（不含纯英文专名字母）；上限约 **48**；再长必须拆成两短句 |
| 每拍时长 | 与 VO 实测对齐，单拍口语约 **5.5–8.5s**；忌 10s+ 念稿 |
| 句式 | 主谓宾清楚；少用长定语、括号、破折号插入语 |
| 换气 | 一句里最多 **1–2 个逗号停顿**；需要第三处停顿 → 拆句 |
| 开场 | Beat 01 必须一听就懂「谁 / 发生了什么」，禁止专名轰炸开场 |

好：`微软 Authenticator 安卓版修了一个漏洞。零权限 App，能冒充 Teams 偷工作号令牌。`

坏：`微软 Authenticator 安卓版曝出已修复漏洞：零权限 App 能冒充 Teams，偷走工作号 Token。CVE-2026-80097，CVSS 八点六；修到 6.2606.4246 及以上，请立刻更新。`（信息过密、符号过多）

---

## 三、中英混排（吃力的头号来源）

1. **每拍英文专名 ≤ 2 个**（产品名/人名/CVE 算一个）。第 3 个改成中文意译，或挪到下一拍/画面字卡。
2. **连续英文专名禁止无连接地念**：不要 `Gemini Omni、Gemini 3.8 Flash、Gemini 4 Argon` 一口气。改成：`底座是 Gemini。Omni 负责外观，Flash 负责环内引导。`
3. **能意译就意译**：`hiring manager` → `招人的工程经理`；`native audio` → `原生音频`；`research preview` → `研究预览`。
4. **必须保留的英文**（品牌/CVE/版本）前后加中文着陆：`漏洞编号是 CVE-2026-80097`，不要孤立甩一串字符。
5. **版本号/分数**：口播用阿拉伯数字自然读法（`6.2606.4246`、`8.6`）；**禁止**写成「八点六」「六月」这类中文数字（与发布文案阿拉伯数字规则一致）。TTS 念版本号若别扭，可说 `六点二六零六版本及以上`。
6. **人名**：首次可「工程经理 Felix」，不必全名+头衔+公司叠罗汉；公司名与人名不要同一拍塞第三次。

---

## 四、新闻播报语气

- **像播报员说话**：完整、稳、口语；不要标题党口号，也不要论文摘要。
- **主动句优先**：`微软已经修好` > `已被修复的漏洞被披露`。
- **边界/免责用白话**：`这是他自己团队的面试做法，不是公司全员规定。` > `口径要分清：这是 hiring manager 的本队实践…`
- **终局拍**：给听得清的判断 + 可执行下一步（更新、候补名单、先看演示），不要「不是传闻」空喊。
- **问句 CTA**（可选）：最多一句，短，真问；不要假大空。

## 四甲、科技频道口播对照（Justin 2026-11-01 · 硬要求）

旁白要对齐**科技频道 / 新闻联播科技口**听感，不是产品白皮书、也不是博客摘要。

### 听感标尺（抽听时默念）
- **谁 + 干了什么** 先落地，再补「意味着什么」
- 一句听完脑子里能画图；卡壳、要回头看 → 不过
- 术语必须**先白话落地**再可选点名；禁止连续两拍都是架构黑话

### 禁止（本条 DeepSeek 翻车点，一律退回）
1. **架构黑话连发**：`Router / Worker / 会话调度 / 合成负载 / 存算分离` 一口气念完。改成生活类比：`上面只管分活，下面专心干活`；`实验是模拟场景跑的，别当发版成绩`
2. **拍与拍同义反复**：开场已说「开源研究原型」，下一拍禁止再空转同一句；每拍必须新信息
3. **书面堆砌**：`并同步开源`、`面向单个…主动…`、顿号清单、破折号插入。改短句 + 逗号换气
4. **画面比嘴更绕**：底栏 `.narrative` 不得比口播更密、更书面；听感与口播同档白话（专名细节可留卡片，解说本身要顺口）
5. **数字别扭念法**：少用 `九成五` 这类半文言；优先 `百分之九十五` / `十二分钟出头` 等播音自然读法

### 好句型（科技频道味）
- `DeepSeek 昨晚公开了一套设计，还开源了研究原型。`
- `目标很直白：一直在线，能同时干多件事，还会自己找活干。`
- `上面只管分活，下面专心干活；环境一有动静，它就能接上。`

### 坏句型（说明书味）
- `上层 Router 只分派，下层 Worker 干活，环境事件一来就驱动行动。`
- `研究原型、合成负载、简化环境；扩展、人机协作、A2A、安全隐私四道开放问题仍在。`

## 四补、新闻播报节奏（Justin · 硬要求）

旁白要像**节奏大师**：听感连续往前推，**不给听众「愣一下再想」的空档**。

1. **句间紧**：拍与拍之间空隙约 **0.35–0.50s**，禁止 0.7s+ 的「留白思考位」。
2. **句尾干脆**：少用拖沓收尾、软着陆的「……」感；事实说完即切下一拍。
3. **信息点跟拍走**：一拍一个点，听完立刻接下一条，不要在旁白里解释「怎么听」。
4. **抽听标准**：全程像新闻联播科技口播——跟着节奏走，而不是播客闲聊。

## 五、与画面分工

| 放旁白 | 放画面大字 / 底栏 / PUBLISH |
| --- | --- |
| 事件主线、利害、边界、行动 | 长专名列表、**精确时间码/「约 X 秒起」**、CVSS 明细、章节秒数 |
| 一个记忆点数字（如 `8.6`、`8 天`） | 三个以上并列功能名 |

功能清单类选题（如 Grok Bot Pages/Vault/…）：旁白只点 **2–3 个代表**，其余「还有密码库、出片、Spaces」一带而过，完整列表进画面或文案。

## 六、TTS 工艺（顺畅的后半段）

默认仍 `zh-CN-YunyangNeural`。稿子过审后：

| 参数 | 标准 |
| --- | --- |
| rate | 默认 **`+8%`～`+12%`**（舒适播报）；信息极简的钩子拍可用到 `+14%`。**禁止**在密专名稿上强行 `+14%` |
| pitch | `-1Hz` 可保留 |
| 标点 | 用句号切开；需要停顿用逗号；少用分号、破折号、英文冒号 |
| mastering | 仍走 `audio_mastering.md` 滤镜链；`data-volume="1.0"` |
| 抽听 | 渲前用系统播放器听完 7 条：有无吞字、赶字、中英打架；有则改稿重录该条 |
